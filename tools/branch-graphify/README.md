# Branch Graphify Analysis

This tool creates **independent, commit-pinned Graphify snapshots** for:

- `main`
- `stage1/section-uuids`

Each invocation analyzes exactly one branch commit in a temporary detached Git worktree. The two invocations do not compare graph nodes, edges, architecture, or Git history. They produce separate structural evidence sets.

## Outputs

The workflow stores the latest snapshots under `branch-graphify-results/latest/`:

- `main/` — Graphify artifacts for the exact `main` commit recorded in `run-metadata.json`.
- `stage1-section-uuids/` — Graphify artifacts for the exact `stage1/section-uuids` commit recorded in `run-metadata.json`.

Each branch directory contains:

- `graph.html` — interactive Graphify map.
- `graph.json` — machine-readable graph.
- `GRAPH_REPORT.md` — Graphify structural report.
- `analysis-report.md` — branch identity, artifact links, and interpretation boundary.
- `run-metadata.json` — branch name, exact source commit, Graphify version, counts, timestamp, and graph digest.
- `graphify-run.log` — extraction and cluster-only output.

No cross-branch delta, merge-base report, ahead/behind count, or symmetric commit inventory is generated by this tool.

## Run locally (Windows / PowerShell)

Requirements: Git with worktree support, Python 3.11+, and Graphify CLI package `graphifyy`.

    py -3.11 -m venv .venv-branch-graphify
    .venv-branch-graphify\Scripts\python -m pip install --upgrade pip
    .venv-branch-graphify\Scripts\python -m pip install -r tools\branch-graphify\requirements.txt
    git fetch origin --prune
    .venv-branch-graphify\Scripts\python tools\branch-graphify\run_analysis.py --repo . --branch main
    .venv-branch-graphify\Scripts\python tools\branch-graphify\run_analysis.py --repo . --branch stage1/section-uuids

A caller may pass `--commit <sha>` to pin a previously resolved branch tip and `--output <directory>` to select an output directory. By default, each invocation writes to `branch-graphify-results/latest/<branch-slug>`.

## GitHub Actions

The workflow runs on pushes to `main` (excluding result-only commits), manual dispatch, and a weekly schedule. It fetches both branch refs once, pins their SHAs, and runs the single-branch analyzer separately for each SHA. It then publishes the two result directories to `main`.

The workflow does not change either analyzed branch. It creates temporary detached worktrees and removes them after each extraction. Publishing generated reports to `main` is a separate final step.

## Interpretation and limitations

- Graphify extracts code structure from one exact source snapshot. A node or edge is not proof of runtime behavior or semantic correctness.
- The presence of a graph-library import, adapter class, or dependency is not evidence that the adapter is invoked.
- A claim that a backend is functional requires separate evidence: a real call path from the audit engine, a supported operation exercised through the adapter, and tests that verify behavior and structural invariants.
- A claim that a backend is dormant requires a bounded search of relevant call paths and explicit coverage of the search scope; absence from a Graphify map alone is insufficient.
- Graphify snapshots do not rank the five graph libraries. They are alternative computation options whose suitability must be assessed against the problem being audited.
- The workflow uses code-only extraction and cluster-only rendering without semantic/LLM labeling. Repository source is not submitted to an external LLM.
- Graphify is pinned to version 0.9.112 in `requirements.txt`.

## Safety

The workflow reads branch commits and writes generated artifacts under `branch-graphify-results/latest/` on `main`. It does not merge, rebase, reset, cherry-pick, or move either analyzed branch ref. The temporary worktrees are detached and removed after analysis.
