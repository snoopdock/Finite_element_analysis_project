# G3.2.1 Incremental Re-verification Architecture

## Scope

G3.2.1 adds fine-grained impact propagation, deterministic re-verification planning, and read-only audit-memory queries on top of G3.2.0 graph evolution.

## New Runtime Modules

- `evolution/impact.py` — change atoms, dependency profiles, dependency index;
- `evolution/propagation.py` — direct and inherited impact assessment;
- `evolution/reverification.py` — versioned deterministic work planning;
- `evolution/memory_queries.py` — read-only historical lookup;
- `evolution/incremental.py` — composition facade.

## Dependency Direction

```text
snapshots/delta
      ↓
impact profiles
      ↓
impact propagation
      ↓
re-verification planning
```

The planner does not import the verification service, rule executor, or finding factory. Execution therefore remains outside the G3.2.1 boundary.

## Conservative Defaults

Fine-grained locality is granted only to analysis types with bounded semantics. Unresolved upstream artifacts cause `recheck_required`. Direct evidence loss and semantic-context change remain stale-producing events.

## Reproducibility

Change atoms, dependency profiles, task identities, plan identities, memory-query identities and policy versions are deterministic and serializable.
