# G3.4.9 — Evidence Semantic Consistency and Provenance Binding

## Scope

This milestone hardens the manually dispatched CI validation proof created in
G3.4.8. It **does not** modify finite-element numerical semantics or proof-store
publication. The stable executor and verifier remain in `main`; the development
branch supplies the `G3.4.9` profile and non-placeholder policy tests.

## Threat model

G3.4.8 used SHA-256 checks to detect damage to detached files, but it did not
independently determine whether a correctly re-hashed JSON report accurately
represented the JUnit test outcomes or the selected source checkout.

G3.4.9's verifier now checks:

1. Detached report and per-file digest/size integrity.
2. JUnit suite totals against individual testcase outcomes, and both against
   the corresponding report counts.
3. Pass/fail/skip stage statuses against exit code and JUnit results; zero-test
   or entirely skipped suites are not accepted as passed validation.
4. Report-level pass state against all declared stages and selected regression
   mode. A `profile` regression mode only passes when its declared regression
   actually ran and passed.
5. Actual argv targets against the Git-committed profile, whose digest must
   match both the checked-out file and its Git commit object.
6. Source and engine commit IDs against two checkouts, and branch/run/attempt
   against GitHub Actions context supplied independently to the verifier.
7. Successful validation-engine unit test summary, exact count, digest and
   length, referenced from the detached report.

## Limits

An attacker with the authority to replace both the `main` validation engine
and its workflow can replace these checks. SHA-256 is an integrity identifier,
not a digital signature or independent attestation. GitHub artifacts are
retained for a configured period and are not perpetual archival storage.
Workflows install dependencies from the checked-out development branch;
execute only branches whose tests you intend to trust.

## Validation

Use GitHub **Actions → Manual Validation Dispatcher**, workflow from `main`,
branch `stage1/section-uuids`, profile `latest`, regression mode `profile`.
Only `workflow_dispatch` is configured; pushing does not start a run.

The evidence verifier deliberately accepts earlier version 1.0 reports in
offline, digest-only mode. New version 1.1 reports include engine unit-test
provenance and the GitHub dispatcher requires strict source/run binding.
