# G3.4.5 Implementation Report — Detached and Streaming Proof Artifacts

## Purpose

G3.4.5 removes large UNSAT proof bytes from the external solver control-plane response while preserving the high-assurance boundary established in G3.4.0–G3.4.4. A solver may identify a proof artifact; it may not choose an arbitrary location or decide whether the proof is valid.

## Runtime architecture

```text
External solver response
        |
        | certificate.kind = unsat_proof_ref
        v
ProofArtifactReference
        |
        | strict metadata only
        v
ProofArtifactStoreRegistry  <--- trusted application registration
        |
        v
LocalContentAddressedProofStore
        |
        | exact size + SHA-256 verification
        v
verified binary handle
        |
        v
StreamingDetachedProofChecker
        |
        +-- cnf-rup/v1
        +-- cnf-drat/v1
        |
        v
repository-owned logical check
        |
        v
VerificationWitness(FORMAL_PROOF)
        |
        v
VALIDATED / CERTIFICATE_COMPLETE_WITHIN_SCOPE
```

`ProofArtifactReference` cannot contain a path, URL, command, executable, or import path. A physical store exists only because trusted application code registered it. The initial local CAS maps SHA-256 to `<trusted-root>/<sha256>.proof` and refuses symbolic links.

## Artifact format

The first detached format is `semantic_cnf_proof_jsonl/v1` with media type `application/x-semantic-cnf-proof+jsonl`.

Line 1 is a strict header:

```json
{"artifact_format":"semantic_cnf_proof_jsonl/v1","proof_format":"cnf-drat/v1","cnf_digest":"..."}
```

Each later line is one structured proof step. RUP allows only `add`; DRAT allows `add` and `delete`. The proof must end with an added empty clause.

The implementation verifies the exact open file first, rewinds it, and then processes lines incrementally. It does not retain the proof-step list. The active clause database is retained because RUP/RAT checking requires it; the implementation therefore does not make an incorrect constant-memory claim.

## External-solver integration

`validate_external_cnf_certificate()` and `ControlledExternalCnfSolverAdapter` now optionally accept a `ProofArtifactStoreRegistry` and streaming proof limits. A valid registered detached RUP/DRAT proof can validate a large external UNSAT claim. Missing stores, corrupt artifacts, unsupported references, malformed lines, or resource limits leave the external result `OBSERVED/PARTIAL` unless an independent bounded repository checker can establish a verdict.

The controlled external solver remains absent from the default active adapter registry.

## Security and semantic boundaries

- artifact integrity != logical validity;
- store registration != verifier activation;
- store ID != arbitrary location authority;
- retrieval failure != SAT;
- proof resource exhaustion != SAT or UNSAT;
- streaming proof checking does not create findings or mutate the semantic graph;
- `external_process.py` remains the only high-assurance module importing `subprocess`;
- the formal router remains inactive.
