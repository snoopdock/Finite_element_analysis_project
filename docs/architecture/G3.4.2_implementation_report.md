# G3.4.2 Implementation Report — External Solver Containment and Certificate Validation

## Scope

G3.4.2 extends the controlled high-assurance layer with an inactive-by-default external CNF solver adapter, a fixed-command JSON subprocess boundary, strict external-solver protocol binding, and repository-owned certificate validation.

## Runtime components

### `high_assurance/external_process.py`

Owns the only subprocess API in the high-assurance package. The runner verifies the registered executable digest before each invocation, never uses a shell, fixes argv in trusted configuration, sends only bounded JSON through stdin, enforces bounded stdout/stderr while the process is running, applies a wall-clock timeout, terminates the process group on violation where supported, uses an ephemeral working directory/minimal environment, and produces a digest-only execution transcript.

The runner explicitly does not claim network or filesystem sandboxing. Execution is denied unless those missing isolation controls are acknowledged.

### `high_assurance/external_solver_protocol.py`

Defines a strict `semantic_external_solver/v1` response contract. Unknown fields are rejected. Responses must bind to request ID, normalized semantic input digest, solver ID, and solver version.

The expected satisfiability answer is intentionally not sent to the external solver.

### `high_assurance/certificate_validation.py`

Separates solver production from certificate validation.

- SAT model certificates are checked independently against every CNF clause.
- bounded UNSAT claims are independently rechecked by exhaustive enumeration;
- false UNSAT is overruled by an independently discovered model;
- unsupported larger UNSAT claims remain observed/partial.

### `high_assurance/external_solver.py`

Combines the controlled process runner, strict protocol parser, certificate checker, validation envelope, execution trace, and standard high-assurance result contract. The adapter ID is `controlled-external-cnf` and its containment mode is `controlled_external`.

## Completeness model

G3.4.2 adds `certificate_complete_within_scope` to `ValidationCompleteness`. This distinguishes a complete independently checked proof/witness from exhaustive search while still satisfying the G3.4 policy requirement that validated evidence fully discharge its declared scope.

## Orchestration

The built-in profile catalog contains inactive policy metadata for `controlled-external-cnf`:

- method: solver;
- cost units: 12;
- maximum evidence ceiling: validated;
- execution mode: controlled external;
- deterministic: false;
- side-effect-free: false.

The profile does not construct a process runner, register a verifier, accept isolation gaps, or activate the adapter.

## Governance

- ADR-067: Controlled External Process Is Not an OS Sandbox.
- ADR-068: Independent Certificate Validation Before Evidence Promotion.
- ADR-069: External Solver Protocol Binding and Inactive-by-Default Registration.

Normative contracts and schemas accompany process containment, protocol responses, certificate validation, and the external CNF adapter.

## Non-goals

G3.4.2 does not enable arbitrary command execution, automatic tool discovery, external SMT/CP-SAT/Lean, DRAT/LRAT checking, network access, implicit graph mutation, finding lifecycle changes, candidate promotion, or audit-memory persistence.
