# G3.4.8 — Verified Test Execution and Content-Bound Evidence

## Problem corrected

G3.4.7.4 wrote a JSON report about declared tests, without invoking pytest. A green GitHub Action thus proved only that reporting succeeded. G3.4.8 changes the dispatcher from **print/profile metadata** to **execute tests and record the observed result**.

## Trust and execution boundary

- GitHub `workflow_dispatch` on `main` is the **only** dispatcher trigger.
- Two separate checkouts avoid copying trusted orchestration code into development branches.
- `main` houses the runner, evidence verifier and engine unit tests.
- The selected development branch houses test implementations, a declarative profile and JSON Schema.
- The runner accepts only versioned profile identifiers; `latest` is determined by numeric version tuples.
- Profile paths are validated to be relative and under `tests/`; arbitrary shell commands, traversal and symlinks are rejected.
- `pytest` is executed with `subprocess.run(argv, shell=False)`, not shell-string concatenation.
- `profile` mode runs regression only if the selected profile enables it; `skip` and `force` remain operator-controlled manual options.
- Per-command subprocess timeout is 30 minutes; GitHub job timeout is 55 minutes.

## Evidence content

`validation-artifacts/` (uploaded on both successful and unsuccessful tests) contains:

- `validation_report.json`: run metadata, selected profile SHA-256, checked-out **target commit SHA** and **engine commit SHA**, observed pytest exit codes, status, test counts and file digests.
- `validation_report.sha256`: detached SHA-256 of the complete JSON file, avoiding the circular self-hash mistake.
- `targeted.log`, `targeted.xml`: observed target-test output and JUnit XML.
- `regression.log`, `regression.xml`: regression output/JUnit when enabled.
- `engine-unit-tests.log`: main-branch engine regression output.

The verifier checks detached report integrity and every log/JUnit digest referenced from that report. No CI run is considered green if targeted/regression pytest exits nonzero.

## Explicit limitations

SHA-256 detects accidental or malicious *post-creation changes relative to the recorded digest*, but **is not a digital signature**, tamper-proof append-only ledger or remote attestation. A party able to replace an entire report and checksum could forge both. A downloaded artifact's integrity should be checked against a trusted external digest if adversarial authenticity matters.

Profiles on the development branch are configuration inputs, but the tests executed are the branch's own Python code. Branch write access must remain limited to trusted collaborators; this dispatcher is not designed for untrusted pull requests.

The `jsonschema` library checks the target branch schema; the runner independently enforces a strict path and version contract so a permissive branch schema cannot disable path restrictions. Other than the dispatcher workflow there is no push-triggered validation.

## Success criteria

1. Engine unit tests pass.
2. Profile passes JSON Schema and builtin validation.
3. Targeted pytest genuinely executes and returns 0.
4. Profile-selected regression genuinely executes and returns 0.
5. Git commit provenance is present for both checkouts.
6. SHA-256 report and referenced files pass the independent verifier.
7. GitHub provides an uploaded artifact to download.

## Follow-on

A future G3.4.9 can introduce a signed/externally anchored attestation and artifact-chain integration **only after** this actual-test-execution milestone passes CI.
