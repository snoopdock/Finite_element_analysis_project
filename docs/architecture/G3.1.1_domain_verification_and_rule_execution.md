# G3.1.1 — Domain Verification and Semantic Rule Execution

## Purpose

G3.1.1 is the first milestone that exercises the generic G3.1.0 verification
substrate with real semantic audit domains. It does not change the fundamental
verification architecture.

## Implemented domains

### Architecture dependency policy

`GraphAttributeConstraintVerifier` checks explicit node attributes around a
selected dependency observation. The example rule flags a production `Module`
that `DEPENDS_ON` or `IMPORTS` an experimental `Module`.

### Scientific relationship completeness

`RequiredRelationshipVerifier` checks whether an audited source entity has a
required typed relationship in the exact graph snapshot. The example scientific
rule requires a `ScientificClaim` to have an outgoing `SUPPORTED_BY`
relationship. A missing relation is a graph-scoped absence, not proof that no
external evidence exists.

### Provenance completeness

`ProvenanceCompletenessVerifier` checks required paths in evidence provenance.
The example rule requires `edge_metadata.source_id`.

## Domain execution chain

```
GraphAnalysisResult
      |
DomainAuditRule
      |
Target selection
      |
VerificationObligation
      |
Named Verifier
      |
VerificationReceipt
      |
RuleEvaluator
      |
FindingFactory (triggered evaluations only)
```

## Candidate promotion

G3.1.1 also adds guarded candidate-to-canonical promotion. Promotion requires a
confirmed receipt explicitly bound to the candidate and records the promotion
receipt and policy in canonical edge metadata.

## Non-goals

- no LLM or GNN is allowed to mutate canonical knowledge directly;
- no graph metric is converted into semantic importance;
- no automatic remediation is implemented;
- no long-term audit memory or graph-delta propagation is implemented here;
- the existing `analysis/semantic_verifier.py` scientific passage verifier is
  not replaced or duplicated by this milestone.
