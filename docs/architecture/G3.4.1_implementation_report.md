# G3.4.1 Implementation Report — Controlled Solver and Executable-Witness Adapter Architecture

## Scope

G3.4.1 extends the G3.4.0 high-assurance layer with two sensitive verification paths while preserving the existing semantic, verification, orchestration, and memory boundaries.

### Added runtime components

- `high_assurance/cnf_solver.py`: bounded exhaustive Boolean CNF adapter.
- `high_assurance/executable_witness.py`: trusted registry and controlled executable-witness adapter.
- explicit activation controls in `HighAssurancePolicy`.
- inactive-by-default orchestration profiles for both new verifier IDs.

### Solver design

The bounded solver accepts an integer-literal CNF encoding and a declared variable count. Instances above the configured bound are rejected before solving. Accepted instances are enumerated deterministically, yielding a satisfying assignment for SAT or full assignment-space exhaustion for UNSAT.

This is intentionally independent of `formal/router.py` and the placeholder formal backends.

### Executable witness design

Executable evidence is restricted to pre-registered callables with deterministic, side-effect-free, network-free descriptors. No source, import path, shell command, or executable path is accepted from obligation parameters.

### Policy change

`controlled_high_assurance_policy/v2` introduces `explicit_activation_required` and `activated_adapter_ids`. Solver, executable-witness, and theorem-prover mechanisms require explicit adapter activation in addition to mechanism permission.

### Orchestration

G3.3's built-in profile catalog now contains policy metadata for `bounded-cnf-exhaustive` and `registered-executable-witness`, but profile presence does not register or activate either verifier.

### Non-goals

G3.4.1 does not activate external SAT/SMT/CP-SAT solvers, Lean, arbitrary subprocesses, shell execution, network execution, candidate promotion, finding lifecycle changes, or implicit memory persistence.
