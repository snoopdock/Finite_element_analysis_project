# Semantic Graph Schema v1

## Status

Draft for G1.5 architecture freeze

## Purpose

This document defines the stable semantic contract for the Semantic Graph Core.

The semantic graph is the source of truth for representing meaning inside the audit engine.

The graph is intentionally independent from:

- NetworkX
- igraph
- graph-tool
- RDF
- OWL
- formal verification systems

Those are future interpretation and computation layers.

The semantic graph stores:

- entities
- relationships
- attributes
- metadata


---

# 1. Core Model

The graph model is:
G = (V, E, R, A, M)

Where:

| Symbol | Meaning |
|-|-|
| V | Nodes/entities |
| E | Relationships |
| R | Relationship types |
| A | Attributes |
| M | Metadata |


A semantic graph is a directed attributed multigraph.


---

# 2. Node Contract

A node represents an identifiable entity.


## Required fields

Every node MUST contain:

```text
id
kind
attributes
Example:
{
    "id": "module.audit_engine.runner",
    "kind": "module",
    "attributes": {
        "path": "audit_engine/runner.py"
    }
}

3. Node Identity

The node ID must be:

deterministic
stable
reproducible

The same entity discovered in two different audits should receive the same ID whenever possible.

Examples:

Module:

module.audit_engine.runner

Function:

function.audit_engine.runner.execute

Class:

class.audit_engine.semantic_graph.SemanticGraph

Future scientific entities:

claim.paper123.claim001
4. Node Kinds

Initial vocabulary:

Software domain
repository
module
package
class
function
symbol
file
Future scientific domain

Reserved:

paper
claim
concept
equation
experiment
dataset
citation

The vocabulary may expand through future schema versions.

5. Edge Contract

An edge represents a typed relationship between two nodes.

Required fields:

source
target
relation
attributes

Example:

{
    "source": "module.main",
    "target": "module.research.evidence",
    "relation": "IMPORTS",
    "attributes": {}
}
6. Relationship Vocabulary

Initial software relationships:

IMPORTS

Module dependency.

Example:

main.py IMPORTS research.evidence
USES

Symbol usage.

Example:

runner USES get_summary
DEFINES

Declaration relationship.

Example:

module DEFINES function
CALLS

Execution relationship.

Example:

functionA CALLS functionB

Future scientific relationships:

SUPPORTED_BY

Claim evidence relationship.

Example:

Claim001 SUPPORTED_BY Paper001
CONTRADICTED_BY

Conflicting evidence.

DERIVED_FROM

Transformation lineage.

7. Relationship Rules

Relationships are directional.

Example:

Correct:

ModuleA IMPORTS ModuleB

Incorrect:

ModuleB IMPORTS ModuleA

unless independently observed.

The graph records observations.

The graph does NOT decide correctness.

Validation and reasoning belong to later milestones.

8. Attributes

Attributes contain additional information.

Examples:

Node:

{
"path": "src/main.py",
"language": "python"
}

Edge:

{
"line": 12,
"source_file": "main.py"
}

Attributes must not replace relationship types.

Bad:

{
"relationship":"dependency"
}

Good:

{
"relation":"IMPORTS"
}
9. Metadata

Metadata describes the origin of information.

Future compatible fields:

{
"created_by":"ASTExtractor",
"created_at":"2026-09-14",
"source":"audit_pipeline"
}

Metadata supports future provenance integration.

10. Provenance Compatibility

11. Serialization Contract

Current format:

semantic_graph.json

Required structure:

{
    "nodes": [],
    "edges": []
}

Future compatible formats:

RDF/Turtle
JSON-LD
PROV-O
12. Backend Independence Rule

The semantic graph model MUST NOT import:

networkx
igraph
graph-tool
SNAP
scipy

Backend libraries belong behind adapters.

Architecture:

SemanticGraph

        |

GraphBackendAdapter

        |

Network Library
13. Reasoning Separation Rule

The graph stores observations.

It does not perform:

architecture validation
ontology inference
OWL reasoning
formal proof

Example:

Stored:

ApplicationComponent MUTATES ScientificState

Future reasoning:

Violation detected
14. Versioning

Future schema changes should create:

Semantic Graph Schema v2
Semantic Graph Schema v3

Breaking changes must not silently modify existing meanings.

15. G2 Requirements

G2 implementations must consume this contract without modifying it.

Expected:

SemanticGraph

      |

NetworkXAdapter

      |

Traversal
Analysis
Visualization

NetworkX is a computation backend only.

Final Statement

The semantic graph is the stable representation layer between:

Observed reality

and

Future semantic analysis.
