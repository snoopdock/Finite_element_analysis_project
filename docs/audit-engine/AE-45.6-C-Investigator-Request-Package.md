# AE-45.6 — C investigator request package

**Status:** request packaging implemented; CI validation pending  
**Branch:** `stage1/section-uuids`  
**Depends on:** validated C0 authorization preflight

## 1. Purpose

C1 transforms a schema-valid task projection, exact B report and valid manual authorization envelope into a bounded investigator request package. It does not instantiate `RepositoryInvestigator`, create a provider, read credentials, dispatch a workflow or call a model.

## 2. Request contents

The package binds:
- case ID, source SHA and task-contract digest;
- exact B report digest and graph fingerprint;
- authorization ID and authorization-envelope digest;
- prompt/investigator source, tool-policy and cost-estimator implementation digests;
- provider/model and authorized budget;
- original task statement and declared scope;
- A findings/decision/limitations, explicitly marked as machine-generated context rather than ground truth;
- B graph snapshot and bounded graph retrieval context with per-query provenance and response digests;
- required source paths, graph target, relation types and mandatory graph interaction/context requirements.

The investigator prompt is capped at 16,000 characters. The complete structured context remains in the request package; the prompt rendering is a bounded summary. No hidden case labels, expected findings, adjudication metadata or machine-reference registry are included.

## 3. Manual-only invariant

The request package always records:
- `manual_dispatch_confirmed=false`;
- `provider_dispatch_permitted=false`;
- `provider_calls_attempted=0`;
- `credentials_accessed=false`.

A valid authorization envelope is necessary but not sufficient to execute C. A separate manual dispatch confirmation and a C2 execution wrapper are still required. The current code has no C execution workflow.
