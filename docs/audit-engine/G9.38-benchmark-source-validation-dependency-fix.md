# G9.38 — FEA Benchmark Source Validation Dependency Fix

## Observed failure

G9.37 repository validation passed. The separate `FEA LLM Provider Benchmark (Report Only)` workflow passed its high-budget authorization guard, but `validate-source` failed during pytest collection with:

`ModuleNotFoundError: No module named 'jsonschema'`

Three tests under `tests/semantic_high_assurance/` import `jsonschema`. The source-validation job installed only the repository `requirements.txt`, which omitted that test dependency. Because the provider matrix has `needs: validate-source`, all three provider jobs were skipped before any LLM call.

## Correction

The workflow explicitly installs `jsonschema>=4.20,<5` after project requirements and verifies the import before running the full test suite. This dependency is scoped to source validation and is not added to the FEA runtime requirements.

A deterministic regression test checks installation order and confirms the workflow remains manually triggered and read-only.

## Expected next behavior

After this patch passes G9.38 validation and is promoted to `main`, rerunning the benchmark should pass source validation. The three provider jobs can then reveal real pipeline/provider issues. The previous run gives no evidence about provider performance because no provider job started.

## Safety

The benchmark remains `workflow_dispatch` only, requires `confirm_high_budget=true`, uses `contents: read`, runs each provider in an isolated job, and uploads evidence without committing or pushing outputs.
