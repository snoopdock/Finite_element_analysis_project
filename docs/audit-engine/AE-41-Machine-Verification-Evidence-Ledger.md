# AE-41 — Machine-verification evidence ledger

## Purpose

AE-41 creates a normalized evidence ledger connecting each AE-32D case to its immutable source commit, verifier revision, successful workflow run, artifact, checks, and observed runtime outcome. It makes machine-established fixture facts traceable without placing those facts in the benchmark's ground-truth field.

## Recorded distinctions

- `verification_status=machine_verified_candidate` means the declared machine checks passed for that pinned fixture.
- `verification_class` and `runtime_outcome` describe the narrow property reproduced or evidence boundary established.
- `primary_benchmark_eligible=false` is mandatory for every ledger entry.
- `human_independent_adjudication=not_performed` is mandatory for every ledger entry.
- The validator requires one ledger record for each manifest case, rejects duplicate or orphan records, and checks that each ledger source commit matches the case record.

The ledger intentionally does not write `ground_truth.label`, `review`, or primary-score eligibility. In particular, a negative-control runtime pass is not a substitute for independent adjudication of the benchmark label, and an ambiguity-boundary check is not proof of a defect.
