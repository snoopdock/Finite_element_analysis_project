# AE-31 / G9.34 — Explicit NaraRouter Models and Free Semantic Scholar Trial

## Scope

This patch updates the report-only live diagnostic and the active Semantic Scholar retriever. It does not enable automatic self-correction, execute model-generated code, apply model diffs, or mutate the target checkout during diagnosis.

## NaraRouter

The diagnostic calls only `POST https://router.bynara.id/v1/chat/completions`. It no longer calls `GET /v1/models` or attempts automatic model discovery. The workflow requires an explicit model selected from the operator-provided list:

- `agnes-2.5-flash` (default)
- `jev`
- `laguna-s-2.1`
- `nemotron-3.5-lightning-free`

The key is read from the `NARAROUTER_API_KEY` GitHub Actions secret and sent as a Bearer token. The code tolerates a secret accidentally stored with a `Bearer ` prefix, avoids logging key material, and returns an actionable authentication error for HTTP 401. If an explicit model call still returns 401, the secret value or key validity must be checked in GitHub; changing the model alias will not repair invalid authentication.

## Semantic Scholar free-only policy

The operator cannot obtain an institutional API key and wants to use anonymous access only. This patch therefore does not require or add a Semantic Scholar key. The retriever now:

- serializes Semantic Scholar search requests even when the overall evidence pipeline uses a thread pool;
- enforces a minimum interval between API requests;
- retries HTTP 429 responses at most twice after the first attempt;
- honors numeric or HTTP-date `Retry-After` values when the delay fits the bounded retry budget;
- avoids retrying before a longer `Retry-After` expires and defers subsequent requests in the same process during that cooldown;
- records HTTP attempt statuses, retry count, backoff time, and stop reason separately from PDF download/OCR outcomes.

This is best-effort behavior. It cannot guarantee that the upstream anonymous rate limit will allow requests.

## Final free-access probe and decision rule

The report-only live probe makes at most three low-volume unauthenticated requests for up to three records, with bounded 429 backoff. It records the attempt sequence, result count and sample titles.

- Two or more records: retain Semantic Scholar under the new pacing/retry controls and monitor the retrieval report.
- Zero or one record after a successful response, or persistent 429 after the bounded attempts: recommend removing Semantic Scholar from the active retrieval pipeline.
- Transport/network failure: classify as inconclusive rather than treating it as proof that the provider itself is unusable.

The recommendation is report-only; it does not remove or disable the provider. If the probe fails the useful-yield threshold, a separate reviewed patch should remove it from active provider orchestration while preserving historical state, evidence records, and provenance.

## Evidence and prompt quality

Repository code is supplied to the LLM with explicit 1-based line numbers. Manifest byte sizes are explicitly distinguished from source line numbers. The model is told not to require an unavailable API key and to recommend deactivation if the free-only bounded probe yields fewer than two records.

## Validation

G9.34 is deterministic: provider HTTP calls are mocked. It validates all configured NaraRouter model aliases, absence of `/models` discovery, 401 handling and secret redaction, probe retry/exhaustion, the two-record decision threshold, Semantic Scholar request pacing/backoff/cooldown, and existing AE-31 report-only safeguards. Live provider calls remain in the separate manually triggered workflow on `main`.
