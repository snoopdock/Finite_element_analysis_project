# AE-45.5 — C provider authorization preflight

**Status:** provider-free preflight implemented; CI validation pending  
**Branch:** `stage1/section-uuids`  
**Depends on:** validated B report, exact graph snapshot and AE-32C investigator contract

## 1. Decision

C0 implements an authorization and provenance preflight only. It does not instantiate a provider, read credentials, send a prompt, make a network request, or dispatch a workflow. Even a successful preflight reports `provider_dispatch_permitted=false`; `ready_for_manual_dispatch` means only that a separate manual execution step may be considered.

## 2. Preconditions

The preflight requires:
- a schema-valid B report with an embedded schema-valid A report;
- exact equality of A/B case, source, task and scoped source-manifest identities;
- the complete A report and decision preserved inside B;
- complete declared-scope coverage with no missing/unreadable paths or truncation;
- a complete graph snapshot with the expected NetworkX adapter wired into AE-32B;
- successful graph retrieval records with per-query provenance matching the graph fingerprint, source manifest and source revision;
- nonempty graph-neighbor evidence and a successful repository summary.

A report with an unresolved declared-scope descriptor (such as the provider-interface case's "related tests and documented runtime behavior where present") is blocked until that scope is resolved. A partial A diagnostic status is not automatically disqualifying when source/graph coverage is complete; the limitations remain visible to C.

## 3. Manual authorization envelope

The strict authorization schema binds:
- exact case ID, source SHA, task digest and B report SHA-256;
- exact graph fingerprint;
- current AE-32C prompt/investigator source digest;
- AE-32B tool catalog and AE-32C tool-policy digest;
- cost-estimator implementation digest;
- provider/model and explicit confirmation phrase;
- hard limits for model rounds, tool calls, tokens per call, finalization tokens, total tokens, elapsed time and monetary cost.

The initial registered cost-estimator profile is Cloudflare Qwen3.8-27B only. It reuses the existing conservative live-evaluation estimator implementation. NaraRouter and OpenRouter remain unsupported by this C authorization profile until a separately reviewed cost estimator is registered. This is a cost-control limitation, not a provider quality ranking.

Hard ceilings are 11 model rounds, 12 evidence-tool calls, 2,048 tokens per evidence call, 6,144 finalization tokens, 30,720 total tokens, 900 seconds and USD 0.50. An operator may authorize lower values. No authorization may exceed these limits.

The envelope contains no API key, token, account ID or credential. Credentials, if ever used, must be injected only into the separate manually dispatched C job after the authorization is validated.

## 4. Output states

- `blocked_manual_authorization_required`: no manual envelope supplied.
- `blocked_invalid_authorization`: schema, binding, provider/model, estimator or budget check failed.
- `blocked_incomplete_B_snapshot`: B source/graph/provenance/coverage preconditions failed.
- `ready_for_manual_dispatch`: all preflight checks passed; no provider call is made.

Every result explicitly records zero provider calls, no credential access and no dispatch permission.

## 5. Implementation

- `evaluation/ae32d/c-authorization.schema.json`
- `evaluation/ae32d/c-preflight.schema.json`
- `tools/ae32d_c_preflight.py`
- `tests/semantic_audit/test_ae32d_c_preflight.py`

The preflight reads B report data and trusted local source files to compute implementation digests. It does not import `providers.factory` or `RepositoryInvestigator`, and therefore cannot instantiate a provider.
