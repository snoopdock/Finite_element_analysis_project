# AE-45.3 — Deterministic condition A runner

**Status:** runner implemented; full workflow validation pending  
**Branch:** `stage1/section-uuids`  
**Depends on:** A0 schemas, A1 rule catalog, A2 semantic primitives

## 1. Purpose and scope

`tools/ae32d_deterministic_audit.py` assembles the bounded semantic primitives into a provider-free condition A report. It is not a benchmark scorer and does not create an official trial record. It accepts only the sanitized task projection and an exact pinned source checkout.

## 2. Execution boundary

The runner:

1. validates the task projection against the strict A/B schema;
2. requires `condition=A_deterministic`;
3. verifies the source checkout's exact Git commit and clean working tree;
4. resolves the declared fixture root and reads only allowlisted declared-scope files;
5. rejects path traversal and symlinks, and enforces file/count/byte limits;
6. computes a source manifest digest over file hashes plus missing/unresolved scope entries;
7. parses `expected_behavior.json` through an allowlist containing only `function` and task-visible input/output cases;
8. performs deterministic lexical search within the declared evidence files;
9. applies the bounded control-flow, exception-contract and data-flow rules;
10. emits an explicit `defect`, `no_defect` or `abstain` decision, coverage, evidence hashes, unresolved questions, limitations and a deterministic execution trace;
11. validates the final report against `condition-report.schema.json`.

The runner does not read case JSON, ground truth, expected findings, review/adjudication fields, machine-reference registry or scorer outputs. It does not invoke graph APIs, execute target code, make network calls, call an LLM or modify the source checkout.

## 3. Decision policy

- **Defect:** a registered deterministic rule establishes the relevant task-contract violation. For unbound-local findings, the missing branch must also be covered by a task-visible contract input case; a lexical or structural witness alone is insufficient.
- **No defect:** all enumerated task-visible return examples pass under the safe interpreter, the scoped initialization analysis is supported, and no relevant limitation remains. This is limited to the enumerated property and examples, not a universal correctness claim.
- **Abstain:** the task lacks a structured contract, evidence is incomplete, dynamic provider behavior remains unresolved, or the supported rule set cannot justify a decision.

Partial evidence remains visible in the report. The provider-interface case is deliberately observational and abstains rather than converting a visible attribute mismatch into a definitive runtime defect.

## 4. Current implementation and known limits

The A runner currently handles the six pinned exploratory fixtures through:
- conditional local assignment / complete-initialization control;
- exception suppression against an explicit `raise` contract;
- stale intermediate bypassed at a return sink, with safe input/output interpretation;
- incomplete provider attribute evidence, reported as observation plus abstention.

It is deliberately narrow. The control-flow analyzer supports only straight-line and `if`-only statement subsets; the pure interpreter supports only bounded literals, names, arithmetic, unary operators, simple comparisons and conditional expressions. Loops, `try` blocks in the generic CFG pass, calls, reflection, dynamic imports and unsupported data-flow constructs are not inferred. The exception rule has its own exact operation/handler subset. Unsupported evidence is surfaced as partial or abstention.

The rule selection currently uses task-visible identifiers and the structured fixture contract. It is an exploratory baseline for these synthetic case families, not a general Python static analyzer.

## 5. Tests and validation

`tests/semantic_audit/test_ae32d_deterministic_audit.py` exercises the runner on the exact pinned candidate, case-matrix and extended-case source checkouts. It verifies each checkout SHA, the expected bounded decision behavior, provider abstention, report schema validation, exact evidence paths, and that B-labelled projections cannot be run as A.

The AE-32D workflow runs this test with the immutable checkout paths. The latest run associated with the report/evidence-path correction is pending. Do not mark A3 complete until the full workflow succeeds.

After CI passes, review the produced in-memory reports for:
