# G9.37 — Semantic Scholar Retirement and Full-Pipeline Provider Benchmark

## Scope

G9.37 has two bounded outcomes:

1. Retire Semantic Scholar from new live retrieval while preserving its implementation and historical provenance.
2. Add provider selection to the FEA application and a manual, report-only matrix workflow that runs the full main pipeline independently against Cloudflare Workers AI, NaraRouter, and OpenRouter.

This does not enable AE automatic self-correction and does not change the existing scheduled/default FEA pipeline workflow.

## Semantic Scholar retirement

The latest bounded anonymous-access probe returned HTTP 429 on all three attempts and no records. The repository does not have an eligible institutional API key. Therefore `research/evidence.py` no longer submits Semantic Scholar requests during active retrieval. The module `research/semantic_scholar.py` is retained, historical source records and provenance fields are not rewritten, and `merge_evidence` continues to retain historical records. Retirement is represented separately from active-provider failures.

## FEA provider integration

The main application supports provider selection through environment variables:

- `FEA_LLM_PROVIDER=cloudflare|nararouter|openrouter`
- `FEA_LLM_MODEL=<explicit model id>`
- `FEA_BENCHMARK_MODE=1` to accept bounded benchmark-only budget overrides
- `FEA_MAX_LLM_CALLS` (1–100)
- `FEA_MAX_TOKENS_PER_CALL` (256–12,000)
- `FEA_BENCHMARK_FORCE_MAX_TOKENS=1` to apply the selected cap to every call, including calls that normally request fewer tokens
- `FEA_LLM_REQUEST_TIMEOUT_SECONDS` (10–600)
- `FEA_LLM_RETRY_ATTEMPTS` (1–5)

Cloudflare uses its existing Workers AI endpoint. NaraRouter uses `https://router.bynara.id/v1/chat/completions`. OpenRouter uses `https://openrouter.ai/api/v1/chat/completions`. Each provider job receives only its own secret. Credentials are not serialized into model-usage stats.

## Comparison design

The manual workflow starts three isolated jobs from the same target branch and commit. Each job resets generated state and cache, runs the same source validation first, invokes `python main.py --config config.yaml`, and attempts publication-integrity validation. No job commits or pushes generated state. Each provider produces a separate artifact with logs, pipeline outputs, state, provider usage statistics, duration, and SHA-256 file digests.

Default matrix models:

- Cloudflare: `@cf/meta/llama-3.1-8b-instruct-fast`
- NaraRouter: `agnes-2.5-flash`
- OpenRouter: `deepseek/deepseek-v4.1-flash-1017`

The default extended-run limits are 8,000 output tokens per call, 80 logical calls per provider, and a 240-minute timeout per provider job. The operator must explicitly confirm the extended budget before dispatch. Token limits are ceilings; the models are not guaranteed to use the full allowance.

## Acceptance semantics

- G9.37 profile acceptance is based on deterministic targeted tests, full regression, and the existing evidence/provenance validation pipeline.
- The live benchmark is not part of deterministic validation and is not run automatically.
- A successful HTTP response is distinct from a successful parsed response, a complete FEA pipeline, and successful publication validation.
- API response usage is reported only when the provider returns usage metadata; the benchmark does not invent token counts.
- Provider/model output is untrusted and remains subject to existing parsing and publication-integrity checks.
- This workflow is a measurement harness, not an autonomous correction system.

## Cost and data handling

The workflow explicitly warns that three extended runs may use substantial provider quotas and incur costs. The OpenRouter DeepSeek model is not designated as free by its model slug. Operators should verify current provider pricing and data-handling terms before sending repository-derived prompts to providers. Only the selected provider's secret is passed to the corresponding pipeline step.
