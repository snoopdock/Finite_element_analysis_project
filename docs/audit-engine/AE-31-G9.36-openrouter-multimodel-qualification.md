# G9.36 — AE-31 OpenRouter Multi-Model Qualification

## Purpose

Extend the report-only AE-31 Semantic Scholar diagnostic to test the configured OpenRouter API key against the three operator-specified model IDs, in addition to the existing Cloudflare and NaraRouter calls.

## Models

- `deepseek/deepseek-v4.1-flash-1017`
- `nvidia/nemotron-3.5-super-vl:free`
- `google/gemma-4-26b-a4b-it:free`

The runner uses the OpenRouter OpenAI-compatible endpoint `https://openrouter.ai/api/v1/chat/completions`, sends the `OPENROUTER_TOKEN` secret only through the Authorization header, does not perform model discovery, and never logs the token.

## Report and acceptance

The report records each requested model, the returned model when supplied, HTTP status, latency, usage metadata, raw-output digest, schema-validation status and error classification. A machine-readable `PROVIDER_RESULT` line supports the workflow's post-upload gate. The gate parses the final machine-readable section after all raw model outputs, so model-controlled text earlier in the report cannot spoof the result.

The workflow passes the OpenRouter qualification gate only if all three explicitly configured models return a successful HTTP completion. Schema validity is recorded separately: a successful API response is not necessarily a usable structured diagnosis. The existing general gate still requires at least one schema-valid diagnosis response.

## Safety and costs

The run remains report-only. No repository code is executed, no patch is applied, no commit/push occurs, and decision memory is not mutated.

The DeepSeek model slug is not a `:free` model and may incur usage charges under the OpenRouter account. The Gemma and Nemotron slugs are free-tier routes but may be rate-limited. Free provider terms may permit logging or model-improvement use of submitted data; operators should not send confidential material to these endpoints. Provider responses remain untrusted hypotheses.
