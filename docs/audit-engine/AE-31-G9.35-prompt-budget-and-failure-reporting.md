# AE-31 / G9.35 — Bounded Evidence Context and Failure Reporting

## Purpose

G9.34 validation passed, but its first live diagnostic stopped before either model call because the fully assembled prompt exceeded the 120,000-character limit. The short failure artifact omitted the Semantic Scholar probe result, and the runner returned exit code 0 after recording `runner_error`.

G9.35 corrects those three issues without enabling automatic self-correction.

## Changes

- Source and architecture files are supplied as deterministic, relevance-selected excerpts under per-file character budgets.
- Original 1-based line numbers are preserved. Omitted source ranges are explicitly marked; selected-range metadata is included in the prompt and report.
- Very long individual lines are visibly truncated and marked. Evidence claims citing truncated lines receive a warning.
- The final prompt is still measured against `MAX_PROMPT_CHARS` before any LLM call. The limit is not silently raised.
- A prompt-construction exception is enriched with the live Semantic Scholar probe result, snapshot digest, evidence manifest, missing paths, selection manifest, and prompt-size measurements.
- The failure artifact records this safe diagnostic context without embedding source bytes or prompt contents.
- The CLI returns nonzero after successfully writing a `runner_error` report. The workflow uploads the artifact with `if: always()` and explicitly fails the job when the report records `runner_error` or is absent.
- Model evidence citations must be fully covered by one visible source-line range. Citations that reference omitted lines or visibly truncated lines are flagged.

## Safety properties retained

- The target repository is treated as read-only data.
- No target code is executed by the diagnostic runner.
- No model-generated diff is applied, committed, or pushed.
- No automatic self-correction is enabled.
- The workflow remains manually triggered with `contents: read` permissions.
- Cloudflare and NaraRouter secrets are redacted from reports and diagnostics.
- The live Semantic Scholar probe remains bounded and unauthenticated.

## Validation

The G9.35 profile runs the AE-31 tests and the cumulative accepted AE-24–AE-30 targets, followed by the repository test suite. Tests cover bounded excerpts, original line numbers, omitted-line citation warnings, long-line truncation warnings, prompt-budget metrics, probe preservation after prompt failure, and nonzero exit status while preserving the report artifact.

Live provider behavior is not tested by this deterministic profile. After G9.35 passes on GitHub, the separate manual AE-31 workflow may be run to produce a real diagnostic report.
