# G3.4.21 — Evidence-bound human claim annotations

## Goal

Collect human **assessments** of generated-text claims while binding each statement to the exact G3.4.20 dossier, G3.4.19 audit, source-file digests and checked-out commit. Human assessments remain **unverified assertions**; this patch does not grant scientific approval or authorize SAT execution.

## GitHub-only two-phase procedure

1. On `main`, manually start `Manual SAT Claim Review Dossier` with an exact source revision, query, proposed text and `max_results` value. Download the dossier JSON. Record `dossier_sha256` and each claim's `claim_index`/`claim_sha256`.
2. Manually inspect cited source *content*, caveats, and relevant independent technical evidence. Construct review JSON such as:

```json
{
  "schema_version": "sat-human-review-submission/v1",
  "dossier_sha256": "<COPY-64-HEX-FROM-DOSSIER>",
  "reviewer_label": "reviewer-self-declared",
  "assessments": [
    {
      "claim_index": 1,
      "claim_sha256": "<COPY-64-HEX-FROM-CLAIM>",
      "verdict": "insufficient_evidence",
      "rationale": "The cited internal record does not provide independent substantiation of this claim.",
      "reviewed_source_ids": ["DEC-G3.4.13-001"]
    }
  ]
}
```

3. On `main`, manually start `Manual SAT Human Claim Annotations`. Set `source_ref` to the **same exact commit SHA**, and repeat the *exact* query, text and result count. Paste the JSON. Download generated review and original audit/dossier artifacts. If the source changed, hashes mismatch and the step fails.
4. Use the original **Manual Validation Dispatcher** with profile `G3.4.21` for tests and regression.

Verdicts: `supported_by_reviewer`, `unsupported`, `insufficient_evidence`, `needs_revision`, `abstain`. A positive verdict is *only a named human opinion*, and is disallowed on missing citations, unresolved citations, unapproved rules and conflicting outcome claims. Unreviewed claims are explicit in the output, not silently approved.

The runner stores `github_actor_observed_not_attested`, not a signature or credential-based review approval. Never enter secrets, sensitive information, or private keys into inputs: the review artifact retains submitted text and rationales. Github artifacts expire according to retention settings. Nothing is automatically committed or written back to `source`.

## Trust boundaries

- `dossier_sha256` binds the reviewed text and source digests; it does not imply semantic entailment.
- Source records are local project history and may be wrong or obsolete. The reviewer must independently assess claims.
- Annotations are not SAT proofs, engineering approvals, authenticated signatures, autonomous training examples or durable memory updates.
- Automatic SAT actions, verified publication, learned-rule promotion and repository writeback remain **false** regardless of individual verdict.
- This is a *temporary handoff layer*. Durable reviewed decisions, if desired, require separately approved, committed records and future policy enforcement.
