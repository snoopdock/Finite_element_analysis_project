# G3.4.1 — Controlled Solver and Executable-Witness Adapters

## Purpose

G3.4.1 proves that solver and executable-witness verification can enter the semantic audit architecture without turning installed tools or audit evidence into execution authority.

## Explicit activation

Sensitive mechanisms now require both mechanism permission and concrete adapter activation:

```text
registered capability
       +
allowed mechanism
       +
activated adapter ID
       -> executable authority
```

The default high-assurance policy activates neither solver nor executable-witness adapters.

## Bounded CNF solver

`bounded-cnf-exhaustive` is a real deterministic reference solver for Boolean CNF problems up to 12 variables. It enumerates the complete truth-assignment space. A SAT result contains a satisfying assignment. An UNSAT result records complete truth-table exhaustion.

Its result is `VALIDATED` only inside the declared Boolean CNF envelope. The adapter explicitly excludes SMT theories, first-order logic, optimization, external solver implementations, and larger instances.

## Registered executable witness

`registered-executable-witness` can execute only a callable that trusted application code registered beforehand. The audit artifact can name the harness and provide JSON-serializable inputs and an expected result, but it cannot provide code or a command to execute.

The resulting witness records harness identity/version and content digests rather than raw inputs and outputs.

## What remains inactive

The repository's existing SAT/SMT/CP-SAT/Lean placeholders remain inactive. G3.4.1 does not route to them and does not claim they are production verifier backends.

## Future work

A future external solver adapter must add binary/tool identity, containment, resource ceilings, certificate validation, and reproducibility semantics before activation. The G3.4.1 contracts are designed to make those requirements explicit rather than implicit.
