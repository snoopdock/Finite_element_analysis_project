# G3.4.4 — Repository-Owned DRAT Proof Checking

G3.4.4 broadens the proof-carrying UNSAT architecture without transferring authority to an external solver or proof-checker binary.

The new `cnf-drat/v1` certificate is a structured sequence of `add` and `delete` clause operations. Additions are accepted when they are RUP or satisfy RAT on the first literal pivot. RAT checking examines every active clause containing the opposite pivot and requires each non-tautological resolvent to be RUP. Deletions alter checker state only and have no semantic meaning outside proof validation. The final operation must add the empty clause.

The reference implementation is deliberately bounded. Step count, proof literal count, clause width, active formula size, and RAT resolvent fan-out all have explicit ceilings. Hitting a ceiling leaves the proof unaccepted; it does not establish the opposite semantic claim.

The built-in proof registry now exposes both `cnf-rup/v1` and `cnf-drat/v1`. External solver output can reach validated evidence only after one of these repository-owned checkers independently accepts the exact CNF-bound certificate. The external solver remains inactive by default unless the existing high-assurance activation and controlled-external policies permit execution.

This milestone still does not activate the placeholder SAT/SMT/CP-SAT/Lean router, parse arbitrary native DRAT files, or run third-party proof-checker executables. Those require separate containment and artifact-lifecycle contracts.
