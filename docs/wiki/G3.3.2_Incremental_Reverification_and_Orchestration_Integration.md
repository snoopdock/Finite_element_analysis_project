# G3.3.2 — Incremental Re-verification and Orchestration Integration

## Purpose
G3.3.2 connects two previously independent capabilities:

- G3.2 determines which historical audit artifacts are affected by graph evolution and require work.
- G3.3 determines how limited verification resources are allocated and escalated.

The integration layer converts eligible `REVERIFY_RECEIPT` tasks into explicit verification objectives only after prior analysis/obligation intent has been replayed against the after-snapshot.

## Pipeline

```text
Graph evolution
    ↓
Impact propagation
    ↓
ReverificationPlan
    ↓
Integration preparation
    ├── replay prerequisite analyses
    ├── rebase prior obligations
    └── preserve verifier authority
    ↓
Cost-aware orchestration plan
    ↓
Adaptive bounded execution
    ↓
Terminal successor receipts
    ↓
Non-destructive receipt reconciliation
    ↓
Optional explicit memory commit
```

## Interpretation boundaries
Budget shortage is not evidence failure. An unscheduled or unsatisfied objective remains unresolved work. A removed semantic target is `not_applicable`, not a failed verifier. Operational priority is not scientific importance. The bridge does not create findings or resolve historical finding lifecycle.

## Verifier authority
Version 1 deliberately preserves historical `requested_verifier_ids`. Cost optimization cannot silently substitute a different verifier. A future verifier-equivalence contract would be required before that becomes legal.

## Memory
No integration operation writes long-term memory automatically. The explicit recorder stores the preparation, plan, adaptive session, executions, replans, reconciliation, successor analyses/obligations/receipts, and the combined result against the after-snapshot.
