# G3.2.2 — Incremental Re-verification Execution and Result Reconciliation

## Purpose
G3.2.2 closes the gap between planning re-verification work and safely executing it.

The new flow is:

```text
Graph evolution
      ↓
Impact propagation
      ↓
ReverificationPlan
      ↓
Explicit replay catalog
      ↓
Dependency-ordered execution
      ↓
Successor artifacts
      ↓
Artifact reconciliation
```

## Replay before execution
Historical audit artifacts are bound to a prior graph fingerprint and semantic context. They cannot simply be reused against a new graph.

G3.2.2 therefore reconstructs the prior graph query and creates new analysis artifacts against the after snapshot. Verification obligations are then rebound using an explicit selection policy.

### Replay selection policies

`exact_ids` preserves exact observation/evidence identities.

`observation_semantics` re-selects the same subject–predicate–object semantic observation and uses its current evidence. This is appropriate for observation-scoped domain rules.

`analysis_scope` re-selects the entire successor analysis. This is appropriate when the original rule explicitly applied to the analysis as a whole.

The executor does not guess which policy was intended.

## Dependency-ordered execution
Tasks are executed according to artifact lineage:

```text
analysis
   ↓
verification receipt
   ↓
finding
```

A downstream task cannot execute successfully when its required upstream artifact failed or became unavailable.

## Reconciliation rather than mutation
Re-execution does not rewrite historical artifacts.

A prior finding may reconcile as:

- persists;
- not triggered in the new state;
- ineligible under the current evidence state;
- target no longer present.

These are current reconciliation outcomes, not automatic lifecycle transitions on the old finding.

## Memory boundary
Execution is side-effect free with respect to long-term audit memory. Persistence occurs only through the explicit execution-memory recorder.

This keeps:

```text
execution
   ≠
persistence policy
```

and preserves the append-only audit-history model.

## Non-goals
G3.2.2 does not add autonomous scheduling, learned prioritization, GNN inference, automatic finding closure, candidate promotion, or topology-based semantic judgment.
