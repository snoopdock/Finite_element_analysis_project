# G3.4.20 — SAT claim-level review dossier

## Why
G3.4.18 retrieves past decisions and G3.4.19 traces *explicit citation markers* in generated text. Neither of those operations proves the text is correct or supported. G3.4.20 creates a deterministic human-review **dossier**, a review request, not an approval, by re-verifying the G3.4.19 audit against the same checkout.

## Inputs and outputs
- Input: a committed decision-memory repository and G3.4.19 `sat-proposal-audit.json`.
- Output: `sat-claim-review-dossier.json` containing a row for each line/claim, cited and missing references, local source-file hashes, historical caveats, blocking review requirements, and a SHA-256 identity digest.
- Deterministic: No timestamps, mutable counters, runtime-generated approvals, or inferred semantic validity. A changed source invalidates re-verification.
- Validation is strict: malformed/duplicate-key JSON, unsafe symlinks, missing references, altered audit data, and modified dossier fields are rejected.

## Claim interpretation
- **uncited**: no citation marker in the original claim.
- **unresolved**: one or more citation IDs are missing.
- **structurally_traced_only**: all citation IDs map to local records, **NOT** that they support the claim.
- `semantic_support_assessed=false`, `human_review.status=pending`, `authorization_granted=false` are mandatory.
- Source hashes bind bytes inside the target checkout. They do **not** authenticate authorship, GitHub as an independent trust root, third-party references, or an external proof artifact.
- A pending action and an alleged successful outcome must not silently become a learned success.

## Manual GitHub UI
1. Place `MAIN_BRANCH/.github/workflows/08_manual_sat_claim_review_dossier.yml` on `main`.
2. Place `STAGE1_SECTION_UUIDS` files on `stage1/section-uuids` without their destination prefix.
3. Run the existing **Manual Validation Dispatcher** from `main`, set target branch `stage1/section-uuids`, profile `G3.4.20`, regression mode `profile`.
4. Optionally run **Manual SAT Claim Review Dossier** from `main`, set branch, query and draft; download the temporary pair of JSON documents.
5. Before any future decision, a reviewer must check claim correctness, external evidence where appropriate, the unresolved caveats and engineering consequences. This patch deliberately provides **no approval-record writing mechanism**.

## Boundaries
No background job; no push trigger; no repository writeback; no SAT solving, solver-control, automatic rule promotion, or generated-text publication. The workflow uploads a 14-day temporary transport artifact, not persistent decision memory.
